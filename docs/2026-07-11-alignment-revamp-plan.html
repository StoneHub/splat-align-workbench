Alignment & Code Revamp

Audit baseline: 2026-07-11 · Product contract: local-first, landmark-driven Sim(3), trustworthy merged PLY.

Alignment verdict

Aligned

Core solve

The source-to-target Horn/Umeyama-style Sim(3) convention is internally consistent, tested for scale, rotation, translation, noise, collinearity, and coplanar warnings.

Needs work

Visual confidence

The overlay still lacks landmark markers and residual vectors, so the user cannot inspect correspondence error in 3D.

Needs decision

Stitch semantics

Join, direction, and plane guides currently gate the workflow but are solved as equal-weight point pairs. Either implement geometric constraints or explicitly teach them as virtual corresponding points.

Known boundaries

  • Merged export intentionally rejects non-vertex PLY element payloads until their preservation semantics are implemented.
  • The current renderer/export lane supports binary little-endian, float32 vertex splat layouts; unsupported layouts now fail explicitly instead of being silently misread.
  • Higher-order spherical-harmonic coefficients are not rotated during export yet. That is an appearance-fidelity gate, not a cosmetic backlog item.
  • No server upload path is introduced. Files remain local in browser memory.
